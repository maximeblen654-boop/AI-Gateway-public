# 模型选择与状态展示 · Oil UI

2026-10-16。用户已选择 **A · 简洁标签**，B/C 仅保留设计比较，不进入产品。

设计目标：先让用户辨认模型，再按需了解已有调用记录。沿用作品桌的暖灰背景、棕色强调和既有字体；模型行右侧只放短标签，详情按悬停、键盘聚焦或点按展开。状态不自动选模型、不触发报价或生成。

三版设计位于 designs/style-explorer.html。设计稿中的模型、错误率与时间均为虚构演示数据，不是生产监控结论。B 的短条表达聚合比例，不是时间序列。正式 A 组件位于 frontend/src/components/video/StudioModelPicker.vue，真实数据来自服务端授权商品目录的 passive_status 字段。

Oil UI 0.22.2 已读取并使用其视觉语言、动效、素材与风格对比页流程；无需额外图片素材。保留原有浮层展开/收起动效，不添加装饰循环；减少动态偏好继续有效。三个设计桌面与390px手机已主线程查看，无独立视觉评审。

真实性边界：只显示当前访问 Group 内、同平台同 requested model 的聚合，不能称为某个 Account 的健康。无数据、监控未启用、样本不足、过期均为中性。错误率沿用原生分类，不等同于作品交付失败率。状态详情不暴露 Key、内部路由、日志正文或其他用户信息。

生产只读核对发现当前 Channel Monitor 运行模式是 V1；V2 配置虽启用，但水位为空、近期无图片/视频聚合。Group31同时有多个Account。本轮不改变生产监控模式，所以生产在部署该功能后仍可能显示暂无状态数据，这是正确结果。

验证分层：设计截图、Vue fixture交互、真实Core/Bridge/BFF候选分别记录。设计稿或fixture通过不代表真实联调通过。最终联调结果以HANDOFF为准。成品截图复核发现手机弹层被顶部导航遮挡，修订为110px以下、视口内限高的浮层；桌面布局保持，四种尺寸/主题回归通过。
