# 旧视频原片兼容迁移方案（未执行）

新政策只适用于能可靠识别的新任务：BFF v3固定48小时，Core有新任务策略标记与原始持久化期限。已有v1/v2及没有新策略的旧任务保持原下载合同，不从quote时间、SQL更新时间、升级时间或首次升级后访问时间推断新的48小时截止。

后续迁移须先获得单独授权，不能把本地开发授权推导为生产历史删除授权。

1. **只读清单。** 按稳定owner/operation/child/task与原账号/模型绑定核对BFF原片metadata、Core哈希proof、receipt和账务终态，输出脱敏数量/大小/已承诺期限。未知身份、损坏、未决或待结算单独标记，不清理。
2. **保留原承诺。** 已有明确deadline直接遵守，不提前缩短。没有明确期限的旧视频不直接套storedAt+48h；先由用户确认历史商业承诺、客户通知及过渡下载窗口。
3. **明确迁移截止。** 拟议新截止不得早于原承诺和经确认的通知/过渡窗口。需要迁移时，制定单一、版本化、幂等的任务身份清单与绝对截止；不通过访问或恢复延长，不用前端隐藏代替服务端控制。
4. **隔离验证。** 在受保护备份副本验证BFF/Core期限一致、到期拒绝、所有副本清理、hash/receipt/claim及未决恢复不丢、清理失败可重试；验证不能靠旧数据库回滚撤销已完成财务事实。
5. **再审批与有限执行。** 只有清单、通知规则、备份和对应兼容版本均审核通过，才申请定向迁移/删除授权。未批准前继续`legacy_unknown`，不批量删除旧原片，也不建立额外永久保存系统。

本轮没有访问生产，所以不提供虚构的旧视频数量、占用或客户承诺结论。当前兼容分支只保证旧视频不会因新48小时政策被直接批量删除。
